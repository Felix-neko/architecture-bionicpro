### 3. Реализованы тесты

#### TestServiceAvailability (2 теста)
- ✅ `test_frontend_is_available` - проверка доступности фронтенда
- ✅ `test_backend_is_available` - проверка доступности бэкенда

#### TestAuthenticationFlow (1 тест)
- ⚠️ `test_login_flow_with_authentik` - полный процесс авторизации через Authentik/Keycloak
  - Открывает фронтенд
  - Нажимает кнопку входа
  - Перенаправляется на Authentik
  - Нажимает кнопку входа через Keycloak
  - Вводит учетные данные в Keycloak
  - **Требует**: пользователь `user1` с паролем `password123` должен существовать в Keycloak

#### TestAuthenticatedFeatures (2 теста)
- ⚠️ `test_frontend_shows_content_after_redirect` - проверка отображения контента после авторизации
- ⚠️ `test_reports_button_shows_jwt_content` - проверка работы кнопки /reports и получения JWT данных

#### TestFullE2EScenario (1 тест)
- ⚠️ `test_complete_user_journey` - полный сквозной сценарий от начала до конца

### 4. Автоматическая проверка сервисов
Перед запуском тестов автоматически проверяется доступность:
- Frontend (http://localhost:5173)
- Backend (http://0.0.0.0:3001)
- Authentik (http://localhost:9000)

Если какой-то сервис недоступен, тесты не запускаются и выводится понятное сообщение.

## ⚠️ Важные требования

### Перед запуском тестов необходимо:

1. **Создать пользователя в Keycloak**:
   - Username: `user1`
   - Password: `password123`
   - Temporary: OFF
   
   См. подробную инструкцию в [TESTING_GUIDE.md](TESTING_GUIDE.md)

2. **Запустить все сервисы**:
   ```bash
   # Docker сервисы
   docker compose up -d
   
   # Frontend (из WebStorm или терминала)
   cd bionicpro-frontend && npm run dev
   
   # Backend
   cd reports_backend && python main.py
   ```

3. **Установить зависимости** (только первый раз):
   ```bash
   uv sync
   uv run playwright install chromium
   ```

## 🐛 Известные проблемы и решения

### Проблема 1: "Connection refused"
**Причина**: Сервисы не запущены  
**Решение**: Запустите все сервисы (см. раздел "Важные требования")

### Проблема 2: "Timeout exceeded" при авторизации
**Причина**: Пользователь `user1` не существует в Keycloak  
**Решение**: Создайте пользователя в Keycloak (см. [TESTING_GUIDE.md](TESTING_GUIDE.md))

### Проблема 3: Тесты падают после входа в Keycloak
**Причина**: Пароль установлен как "Temporary" или неверный  
**Решение**: Убедитесь, что:
- Пароль `password123` установлен
- Опция "Temporary" выключена в настройках пользователя

## 🎯 Что тестируют E2E тесты

### 1. Доступность сервисов
- Фронтенд отвечает на запросы
- Бэкенд отвечает на запросы
- Authentik доступен

### 2. Процесс авторизации
- Открытие фронтенда
- Нажатие кнопки "Войти через Authentik"
- Редирект на Authentik
- Выбор входа через Keycloak
- Ввод учетных данных
- Редирект обратно на фронтенд
- Проверка успешной авторизации

### 3. Функции после авторизации
- Отображение информации о пользователе
- Работа кнопки "Вызвать GET /reports"
- Получение данных от бэкенда
- Проверка содержимого JWT (username, email, groups, uid)

### 4. Полный сценарий
- Весь путь пользователя от начала до конца
- Проверка всех компонентов системы
